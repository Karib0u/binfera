# Prototype packs

`winapi64.pack` and `winapi32.pack` also hold Microsoft's Win32 metadata (`Windows.Win32.winmd`, from microsoft/windows-rs at commit `2670070e0a7d31ff6309d61890fcbc9a5799e456`, MIT OR Apache-2.0, read with the `windows-metadata` crate). `scripts/decompiler_types/pack_win32_metadata.py` adds 10,715 (x64) and 10,711 (x86) prototypes that the Ghidra archives lack (WinINet, WinHTTP, Toolhelp, BCrypt, netapi, GDI+, LDAP and others), every struct, union, enum and handle typedef of the metadata, `P:<function>` records that name the enum or flag set each parameter takes, and `E:<name>` records with the named values of those sets (1,065 x64, 1,064 x86) and of the `HKEY` constants, which the symbolic-constants pass prints (`docs/decompiler-design.md`). Entries already in the pack keep priority. The native API (`Nt*`, `Zw*`, `Rtl*`, `Ldr*`: 1,613 x64 and 1,608 x86 prototypes) and the loader structures `_PEB`, `_TEB`, `_PEB_LDR_DATA` and `_LDR_DATA_TABLE_ENTRY` come from the phnt headers of winsiderss/systeminformer at commit `bfef6c7e7d419bb3dea195eb8149b80f3574d324` (MIT), parsed with Ghidra's C parser; 44 MSVCRT/UCRT startup and helper prototypes are in the fixed-signature supplement. Totals: `winapi64.pack` 43,123 prototypes and 43,667 types, 4,126,180 bytes, SHA-256 `3249112b440b86aff78c99239c417ee1be5d5e9e8dff7ccfc946646c024e251e`; `winapi32.pack` 42,995 prototypes and 43,603 types, 4,112,189 bytes, SHA-256 `24197b806f5320a7217421af56932c202ff3db60d4e22197cf62ba839fdc36d4`. The data describes the Windows SDK headers; Microsoft redistributes this file under MIT OR Apache-2.0, which binfera relies on (see `NOTICE`). Regeneration: `scripts/decompiler_types/README.md`, "Win32 metadata", "Native API" and "C runtime".

`winapi64.pack` is generated, not hand-edited. Source: Ghidra 12.1.4 (`Ghidra_12.1.4_build`, commit 8b6bbb857accdfa20dc5b2f5dea471178c2e9fbc) `Ghidra/Features/Base/data/typeinfo/win32/windows_vs12_64.gdt` and `generic/generic_clib_64.gdt`. With the kernel header and fixed-signature supplements: 30,751 function prototypes and 9,704 named types in Ghidra's decompiler marshalling. Format and regeneration: `scripts/decompiler_types/pack_prototypes.py` and its README. Use is described in `docs/decompiler-design.md`.

`winapi32.pack` is the x86-32 counterpart. Source: the same Ghidra 12.1.4 `windows_vs12_32.gdt` and `generic/generic_clib.gdt`. With the kernel and fixed-signature supplements: 30,634 function prototypes and 9,650 named types, 1.5 MB, exported with an x86-32 program so that pointer sizes and calling convention names come from `x86win.cspec`. SHA-256 `ac448f7ffa5c6019c4a261032477f6b35a4202b650fe76232859ae12656a8b38`.

The Windows kernel supplement comes from MinGW-w64 14.0.0 DDK headers and ReactOS 0.4.15-release `fltkernel.h` (public domain), parsed for each target with Ghidra's C parser. It adds kernel, HAL, NDIS, filter-manager and native API signatures without replacing existing Win32 or C library functions. `winapi64.pack` SHA-256: `ec6e2ad92297a2b704926625659ce410cd88c7daeb7c5c0af40ee021c9e0b522`. Regeneration and limitations: `scripts/decompiler_types/README.md`, "Kernel and native Windows APIs".

`sysv64.pack` is the System V x86-64 (Linux) counterpart. Source: the same Ghidra 12.1.4 `generic/generic_clib_64.gdt` alone (there is no POSIX or Linux archive in the release), exported with an ELF x86-64 program so that calling convention names come from `x86-64-gcc.cspec`: 6,633 function prototypes and 1,229 named types, about 200 KB, including the fixed-signature supplement. It covers the C library and the POSIX headers that archive carries (`socket`, `pthread_create`, `execve`, `mmap`), plus dynamic-loader calls. Raw Linux system calls use separate models. Regenerate with the x86-64 command in `scripts/decompiler_types/README.md`, importing `binfera/tests/fixtures/elf64_sysv/freestanding.elf` and listing only `generic_clib_64.gdt`.

`sysv32.pack` is the System V i386 counterpart: the same Ghidra 12.1.4 `generic/generic_clib.gdt` alone, exported with an i386 ELF program so that calling convention names come from `x86gcc.cspec`: 6,633 function prototypes and 1,229 named types, about 200 KB, including the fixed-signature supplement. SHA-256 `c4da33697ea2377d287f32c351b63599a474313e42e6a61b5201359b6be329ad`. Regenerate with the i386 command in `scripts/decompiler_types/README.md`, importing `binfera/tests/fixtures/elf32_sysv/freestanding.elf`.

`golang64.pack` and `golang32.pack` hold Go standard library signatures and the Go types they use, for amd64 and 386. Source: Ghidra 12.1.4's Go API snapshots, `Features/Base/data/typeinfo/golang/go1.15.0.json` to `go1.25.0.json` (the `.gdt` archives beside them are not used). `golang64.pack`: 33,859 functions and 3,984 type definitions over the eleven releases and Windows, Linux and macOS, 1.7 MB, SHA-256 `dc056c414e2d38e8c43935da5c1d8206d35ba04dcb97b0fb655a6492fe6d18c6`. `golang32.pack`: 33,153 functions and 3,850 definitions (Windows and Linux), 1.6 MB, SHA-256 `6c207da4e02df06b2b3bb21574f6f3a6459474862e0b77d4ef91afe65436a16e`. Regenerate with `scripts/decompiler_types/pack_go_snapshots.py` (see its README); no Java is needed.

## Linux syscall names

`linux32_syscalls.txt` and `linux64_syscalls.txt` contain numeric ABI facts extracted from Linux v6.12's `arch/x86/entry/syscalls/syscall_32.tbl` and `syscall_64.tbl`, respectively. The x32 ABI is excluded. Regenerate with `python3 scripts/decompiler_types/linux_syscall_names.py`. Sources: [i386](https://github.com/torvalds/linux/blob/v6.12/arch/x86/entry/syscalls/syscall_32.tbl) and [x64](https://github.com/torvalds/linux/blob/v6.12/arch/x86/entry/syscalls/syscall_64.tbl).

The native bridge follows Ghidra's `ResolveX86orX64LinuxSyscallsScript` approach of named call replacements and uses its vendored `syscall` calling conventions. Its raw parameter descriptions are based on Linux's [syscall declarations](https://github.com/torvalds/linux/blob/v6.12/include/linux/syscalls.h) and [x86 mmap/clone layouts](https://github.com/torvalds/linux/tree/v6.12/arch/x86/kernel). Only C archive signatures with matching kernel arguments are reused. Raw kernel returns use a signed machine word rather than libc's error conversion or pointer result types.

## Fixed-signature supplement

Run `scripts/decompiler_types/supplement_prototypes.py` after exporting the C archives, including the Windows kernel export. It adds missing loader, stack-protector, Objective-C, CoreFoundation and native Windows declarations without replacing archive entries. Sources and all five regeneration commands are in `scripts/decompiler_types/README.md`.

`macos64.pack` now contains 14,256 function prototypes and 3,250 named types. SHA-256: `42de4e46b383902580339265015224e0b5771585d809a44fad99899dd31b1512`. `sysv64.pack` SHA-256: `6bcded2c3a969b6036f2746c3002449d8cc90e5dad7c817eb4b901f30618e68d`.
